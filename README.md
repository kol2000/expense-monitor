# Expense Monitor

Приложение для личного учёта расходов на собственном сервере: импорт истории EasyFinance, получение операций из Дзен-мани и ручной ввод. Русскоязычный адаптивный веб-интерфейс со светлой и тёмной темами.

Стек: Python, SQLite, Gunicorn и Docker Compose. Подходит для Linux-сервера или виртуальной машины, в том числе на Proxmox. Приложение рассчитано на одного пользователя и пока активно развивается.

## Возможности

- Импорт расходов из CSV EasyFinance с защитой от повторной загрузки неизменённых строк.
- Получение изменений из Дзен-мани каждые 15 минут и по кнопке; без записи изменений обратно.
- Ручной ввод, простые категории, месячные итоги и сверка двух источников.
- Исключение переводов между своими счетами и ручной разбор неоднозначных операций.
- Хранение данных на своём сервере, CSV-экспорт и резервные копии SQLite.

Для автоматической загрузки банковских операций нужен аккаунт Дзен-мани с настроенным сбором данных. Прямых подключений к банкам у Expense Monitor нет. Без Дзен-мани доступны импорт EasyFinance и ручной ввод.

## Правила учёта

- Точная сумма хранится в копейках. В отчёте **каждая** покупка округляется вверх: 1347,27 → 1348 ₽; 248,80 → 249 ₽. Целые суммы не меняются.
- Переводы между известными собственными недолговыми счетами исключаются, включая переводы в инвесткопилку и операции в обработке. В карточке показываются исходный и целевой счета; такой перевод нельзя включить в расходы. Переводы с долговыми/неизвестными счетами, а также операции с признаками «перевод», «СБП», `transfer` предлагаются для ручного разбора. Оплату человеку можно пометить расходом.
- Автоматическая классификация не гарантирует распознавание всех переводов. Просматривайте поступившие операции. Поступления/возвраты/кешбэк пока не уменьшают расходы автоматически.
- Возможные переводы физлицам отправляются на разбор и до решения не входят в расходы. Проверяются категория, получатель и комментарий (перевод, СБП, transfer, card2card, p2p), а также русские имена с инициалами или отчеством. Эти признаки могут потребовать уточнения; обычная оплата через СБП тоже попадает на разбор. Проверка применяется и к ранее загруженным операциям. Явные решения пользователя сохраняются; ручные расходы не переклассифицируются. Без признаков перевода в данных распознать получателя надёжно невозможно.
- Единственная валюта — рубль. Все импортируемые суммы трактуются как рубли без проверки валютных справочников и без конвертации. Подключайте только рублёвые счета. Незавершённое списание ожидает проведения банком; после обновления из Дзен-мани статус пересчитывается автоматически.
- До даты перехода учитывается EasyFinance; с неё — Дзен-мани и ручные записи. Дата по умолчанию 15.10.2026, меняется в интерфейсе. Это **дата начала нового учёта**, а не дата прекращения работы в EasyFinance.
- При параллельном ведении двух систем: последующие строки EasyFinance служат для сверки и не удваивают расходы. Сверка по дате и округлённой сумме предварительная; одинаковые покупки сопоставляются по одной, без удаления повторов.
- Десять стартовых категорий, без вложенности. Их можно переименовать, добавить или объединить через переименование в существующую. Названия исходных категорий сохранены; таблица соответствий редактируется.

## Установка на VM

Требуются Linux, Git, Docker Engine и плагин Docker Compose с поддержкой `up --wait`. Для постоянного доступа настройте reverse proxy с HTTPS либо используйте SSH-туннель. Команды ниже выполняются в терминале сервера; SSH-туннель запускается на клиентском компьютере.

```sh
git clone https://github.com/kol2000/expense-monitor.git
cd expense-monitor
cp .env.example .env
chmod 600 .env
# Откройте .env редактором и задайте APP_PASSWORD (не менее 12 символов).
# ZENMONEY_TOKEN можно добавить позже.
docker compose up -d --build --wait
```

Если Docker требует повышенных прав, запускайте команды `docker compose` с `sudo`. Скрипт обновления сам использует `sudo` при необходимости; весь скрипт запускайте от обычного пользователя.

Приложение по умолчанию слушает **127.0.0.1:8080** на VM. Направьте HTTPS reverse proxy на этот адрес. Если reverse proxy находится на другой машине, задайте BIND_ADDRESS равным адресу VM в локальной сети и разрешите доступ к порту только от proxy. Не меняйте COOKIE_SECURE=1 при HTTPS.

Для первого теста через SSH-туннель можно временно задать `COOKIE_SECURE=0`, оставить BIND_ADDRESS=127.0.0.1, выполнить `ssh -L 8080:127.0.0.1:8080 user@vm` и открыть http://127.0.0.1:8080 на своём ПК. Верните COOKIE_SECURE=1 при переходе на HTTPS. После изменения .env выполните `docker compose up -d`.

Авторизация — один пароль приложения, сессия в HttpOnly/SameSite cookie. Токен Дзен-мани хранится только в .env сервера и не отдаётся браузеру. Операции, выгрузки, база и секреты исключены из Git и Docker build context. Код не зависит от Google-логина: нужен отдельный API-токен Дзен-мани. Получите токен согласно [документации API Дзен-мани](https://github.com/zenmoney/ZenPlugins/wiki/ZenMoney-API). Не вставляйте токен в issues, коммиты или команды shell history.

## Первый запуск

1. Войти с паролем из `.env`. Если есть история EasyFinance, загрузить CSV в разделе «Категории и данные». Поддерживаются Windows-1251 и UTF-8, разделитель `;`, десятичная запятая.
2. Просмотреть предложенные соответствия категорий. Они основаны на названиях и могут потребовать исправлений.
3. Добавить ZENMONEY_TOKEN в .env, пересоздать контейнер, нажать «Обновить из Дзен-мани». Автообновление — каждые 15 минут. Первая синхронизация запрашивает все доступные API данные, следующие — изменения. Запись обратно в Дзен-мани не выполняется.
4. В «Категории и данные» установить свою дату начала нового учёта. Начальное значение `15.10.2026` — значение по умолчанию, его нужно проверить. До выбранной даты отчёты используют EasyFinance, начиная с неё — Дзен-мани и ручные записи. Если историю EasyFinance не используете, выберите дату не позже самой ранней операции, которую хотите учитывать.
5. Расходы, которые не придут из Дзен-мани, вносить вручную. Для оплаты криптовалютой укажите рублёвый эквивалент и при желании исходную сумму в комментарии. Оплату картой повторно вручную не добавлять: межисточниковое автоматическое объединение ручных и банковских записей пока не реализовано.
6. Периодически загружать актуальную выгрузку EasyFinance и запускать сверку за месяц.

Повторные неизменённые строки CSV не добавляются. Одинаковые строки, которые встречаются в самой выгрузке несколько раз, сохраняются в том же количестве. Если старую запись отредактировать в EasyFinance, её новая версия считается отдельной: исключите предыдущую вручную после проверки. Удаление строк в EasyFinance не удаляет их в приложении. Импорт проходит целиком в одной транзакции; файл с ошибкой не импортируется частично.

На Android откройте HTTPS-адрес в браузере и добавьте на главный экран. Есть адаптивная вёрстка и web manifest; офлайн-ввод, service worker и нативный APK в v0.1 не реализованы. Для доступа вне дома нужен доступ к VM через вашу сеть/VPN или настроенный HTTPS proxy.

## Обновление и резервные копии

```sh
sh scripts/update.sh
```

Скрипт делает согласованную SQLite-копию перед обновлением, сохраняет её на VM в `backups/`, выполняет `git pull --ff-only`, пересобирает контейнер и ждёт healthcheck. Изменения в Git, конфликты или ошибка сборки остановят скрипт. База находится в именованном Docker volume `ledger`, сохраняется при пересборке. **Не используйте `docker compose down -v` для обновления.**

Ежедневные копии создаются внутри volume в `/data/backups/` и пока не удаляются автоматически. Настройте отдельное копирование на NAS/другой диск: копия в той же VM не защищает от потери VM. Пример ручной копии:

```sh
mkdir -p backups
chmod 700 backups
docker compose exec -T -e BACKGROUND_WORKER=0 app python -c "from app import ledger; ledger.backup('/data/manual.sqlite3')"
docker compose cp app:/data/manual.sqlite3 backups/manual.sqlite3
```

Восстановление (остановить приложение до замены базы):

```sh
docker compose stop app
docker compose run --rm --no-deps --user root -e BACKGROUND_WORKER=0 -v "$PWD/backups:/restore:ro" app python -c "import shutil; from pathlib import Path; p=Path('/data'); shutil.copyfile('/restore/manual.sqlite3',p/'ledger.sqlite3'); [(p/n).unlink(missing_ok=True) for n in ['ledger.sqlite3-wal','ledger.sqlite3-shm']]; import os; os.chown(p/'ledger.sqlite3',10001,10001)"
docker compose up -d --wait
```

Перед восстановлением сохраните текущую базу отдельной копией. CSV-экспорт из интерфейса удобен для просмотра, но для полного восстановления категорий, решений и курсора синхронизации используйте SQLite backup.

## Разработка и проверка

Бизнес-логика и тесты работают на стандартной библиотеке Python 3.13+. Gunicorn нужен только для production Linux-контейнера. Для локального предпросмотра задайте APP_PASSWORD, COOKIE_SECURE=0 и выполните `python app.py` (слушает только loopback). Встроенный сервер предназначен только для разработки.

```sh
python -m unittest discover -s tests -v
```

GitHub Actions запускает тесты и собирает Docker-образ. Один worker Gunicorn обязателен: сессии и блокировка синхронизации находятся в памяти процесса. После перезапуска требуется повторный вход. Несколько потоков поддерживаются.

## Ограничения и участие в разработке

Это учёт расходов, а не полноценная система бухгалтерии: нет расчёта остатков по счетам, нескольких пользователей и автоматического объединения ручных и банковских записей. Распознавание категорий и переводов использует правила и требует проверки. Перед переходом на единственный источник учёта сверяйте итоги и проверьте восстановление резервной копии.

Сообщения об ошибках и предложения можно оставлять в [Issues](https://github.com/kol2000/expense-monitor/issues). Указывайте шаги воспроизведения и ожидаемый результат. Используйте вымышленные примеры; не публикуйте `.env`, токены, настоящие выгрузки, базы и скриншоты с личными финансовыми данными.

### Визуальные отчёты

Периоды: месяц, квартал, календарный год или произвольный диапазон до десяти лет. Можно сравнить суммы двух выбранных периодов, в том числе по отдельной категории. Для сравнения выбирайте сопоставимые по длительности и полноте периоды. Цвет категории зависит от её названия и сохраняется при переключении дат и сортировке.

Кольцевая диаграмма показывает распределение расходов; список рядом — суммы, доли и количество операций. Нажатие на сектор открывает подкатегории, следующий уровень — операции. В первую очередь показываются назначенные пользователем подкатегории, затем сохранённые категории источника. Записи без детализации показаны как «Без уточнения».

Столбчатый график показывает дни месяца или месяцы выбранного диапазона и учитывает выбранную категорию. Длинный график прокручивается горизонтально. Стрелки переключают месяц, квартал или год; для произвольного диапазона задайте даты вручную. Отчёты используют те же правила даты перехода, исключения переводов и округления каждой операции, что и основной обзор.

### Правила и подкатегории

В «Категории и данные» можно создавать и переименовывать подкатегории. Переименование в существующее название объединяет их. Основные категории, включая «Покупки», автоматически не разделяются.

Правило сопоставляет получателя Дзен-мани с категорией и необязательной подкатегорией: полное совпадение или вхождение текста, без учёта регистра. Правила действуют на историю и новые операции. При нескольких совпадениях применяется первое созданное правило. Его можно изменить или удалить. Кнопка «Правило для получателя» в редакторе операции заполняет форму настройки.

Индивидуальная категория операции имеет приоритет над правилами. Кнопка «Вернуть автокатегорию» снимает индивидуальную классификацию. Правила не меняют суммы, статус проведения, исключения и данные в Дзен-мани.

### Ручные расходы и телефон

В редакторе ручной операции кнопка «Сумма, дата и описание» открывает полную форму. Удаление переносит запись в корзину; восстановление доступно в «Категории и данные». Корзина не входит в отчёты. Банковские операции таким способом не удаляются.

Черновик новой записи сохраняется в localStorage этого браузера и восстанавливается при повторном открытии формы. Успешное сохранение или кнопка очистки удаляют черновик. Он не переносится между устройствами. На телефоне доступна закреплённая кнопка добавления и крупные элементы формы. Приложение можно добавить на главный экран через меню браузера; режим установки зависит от браузера и HTTPS. Финансовые данные не кешируются для работы офлайн.

### Проверка и сверка

Раздел «Требует внимания» отдельно показывает ожидающие проведения покупки, неоднозначные операции, расходы в «Прочем» без индивидуального назначения или правила и возможные дубли ручных и банковских записей. Поиск дублей сравнивает сумму после округления и даты с разницей не больше трёх дней, включая соседние месяцы. Ничего не удаляется автоматически: можно отметить разные расходы или исключить ручную запись. Исключение обратимо через список операций. Изменение суммы, даты или описания приводит к повторной проверке ранее отмеченной пары.

Сверка EasyFinance сначала сопоставляет одинаковую дату и округлённую сумму. Затем предлагает пары с одинаковой суммой и разницей до трёх дней либо разницей до одного рубля в тот же день, внутри выбранного месяца. Каждая запись используется в одной паре. Пары показаны рядом; отметку «проверено» можно отменить. Проверка не меняет финансовый итог. Совпадение не является доказательством идентичности операций; однозначность проверяет пользователь.

Все новые настройки, правила и отметки сохраняются в SQLite и входят в существующую резервную копию базы. Внешние NAS и Proxmox это обновление не настраивает.
